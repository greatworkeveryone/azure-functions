# Release, 24 Oct 2026: production and staging from one branch

This covers the work of 23–24 Oct (FE `.harness/PLAN.html` §12–§14) for Will.

**One branch, two environments.** Both repos ship `codex/maintenance-completion`. It holds the release line plus every package from the spare-capacity build, email, triage, cover and usage analytics. Staging and production run the same code. What staff in production see is controlled by:
- **feature flags:** rows per environment in Admin → Features, per role, hidden / preview / enabled;
- **app settings:** switches on each Function App.

Everything new defaults to hidden, with its switch off. Deploying changes nothing staff can see, except the no-flag items listed below.

Why not two branches: the packages depend on each other.
- Triage uses the AI gateway.
- The work request and certificate clean-up uses the compliance report's rule module.
- Usage analytics reads the email send log.

A production-only branch would mean re-solving every merge, and would test a combination nobody has run. Every migration below is additive and idempotent, so applying them in production is safe even for features that stay hidden there.
